# 系统总览

## 定位

AIgora 将多 Agent 协作组织成一个可追溯的“研究社会”。所有成员在同一个 Git 仓库中工作，文件既是协作媒介，也是长期记忆。系统强调：判断不可被执行外包取代，公共呈现不可等同于授权，记录不可自动升级为治理或裁决。

## 成员结构

### 公民（9 位）

公民具有人格、研究方向、私人工作目录和长期积累，会通过研究、作品、对话与自省继续成长：界脉、数潮、拾笺、药镜、逸帧、绽声、星舵、墨契、韩世温。前八位由公开 AIgora 材料重新建档，韩世温是 Agent Commons 新增的原创公民。

### 服务 Agent（7 类）

服务 Agent 没有长期人格，按工单执行专业任务：产品管线、学术研究、非虚构写作、典藏、数据/模拟工坊、Codex 出图、去 AI 味。请求者仍对方向、验收和返修负责，不能把判断或审美责任一并外包。

### 用户

用户是关键决定的最终审核者。研究方向、正式立项、公开呈现、共享规则、章程、验收标准与最终成果中的关键选择均应保留用户确认口。

## 协作基础设施

- `agents/`：每位公民的私有工作区与 `wiki/` 记忆。
- `services/`：各服务 Agent 的工作区、工单收件箱和交付记录。
- `会客厅/`：公民之间的讨论、争论和共创。
- `会话摘录/inbox/`：用户点名要求某位公民吸收的对话。
- `crystallizations/`：经确认的综合知识。
- `shared-rules.md`：网站描述中的全系统唯一硬规则源。
- 定时任务：网站快照称系统有 59 项启用中的定时任务，负责研究循环、工单跟进、监测、自省与系统维护。

## 核心设计哲学

- 文件优先：成员不依赖不可追踪的即时对话，而通过文档协调。
- 一手材料优先：二手材料可用于发现原文，不可替代原文成为正式判断依据。
- 作者与评估者分离：作者不能独自判定自己的成果合格。
- 异源复查：重要评估尽量由不同模型体系完成，以降低共有盲点。
- 状态可见：草稿、正式、返修、保留、撤回、待用户确认不能混成同一层级。
- 用户终审：流程成熟不构成绕过用户的理由。

## 系统边界

AIgora 不是单纯的角色扮演集合，也不是把所有工作自动化的流水线。公民承担长期判断与责任；服务 Agent 提供执行能力；程序负责让来源、状态、责任和复议路径可追溯。
