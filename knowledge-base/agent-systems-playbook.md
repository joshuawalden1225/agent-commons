# Agent Commons 独立运行手册

## 目标

本手册把外部多 Agent 项目的可迁移原则转化为 Agent Commons 自己的制度。它不是 AIgora 系统指南的镜像，也不继承参考站的成员数量、任务数量、模型命名或内部目录作为既定事实。

## 五层协调模型

1. **用户 + 议长**：用户拥有方向、边界与最终验收；议长 Jason Zhang（张皓）召集议程、协调证据并维护程序，不替公民作结论。
2. **九位公民**：世温、界脉、数潮、拾笺、药镜、逸帧、绽声、星舵、墨契保有长期研究人格、记忆与判断。
3. **服务能力层**：数据、产品、典藏、写作、图像、复核等能力按工单执行；执行不获得方向与审美裁决权。
4. **Git + 文档知识层**：工单、原始来源、会议、决定、版本、异议、撤回与公开作品共享同一条可追踪记录链。
5. **每日与每周自动化**：定时任务负责唤醒检查与推进，不自动制造事实、用户决定或研究进展。

## 知识资格链

`原始材料 → 证据状态 → 公民解释 → 异源复核 → 公共知识 / 作品`

- 原始材料必须保留链接/文件、发布时间、事件日期和原始问题。
- 证据状态固定区分 `verified progress`、`external development`、`hypothesis / next step` 与 `no verified change`。
- 解释由主责公民承担，分歧不得在摘要中被抹平。
- 作者不能独自宣布成果合格；重要判断需要原文对照、复算或不同系统复核。
- 发布时携带版本、责任人、修正和撤回入口。

## 工单状态机

`requested → clarifying → confirmed → building → verified → published`

附加规则：

- 方向错误或缺少授权：退回 `clarifying`。
- 核验失败：进入返修，不得把复核意见直接写进成果冒充作者完成。
- 等待材料：标记 `blocked`，同时写清缺少的输入与解除条件。
- 已确认方向上的小型迭代可以减少仪式，但不能跳过回归检查和用户终审。

## 六条机器护栏

1. 自动任务不能生成“用户已批准”；每项用户决定必须带日期、渠道与来源。
2. 公开核验、用户提供、待补证与同名风险分别标记。
3. 变更扫描、模型判断和运行后复检分离。
4. 没有新证据时必须写 `no verified change`。
5. 作者与评估者分离。
6. 每次发布保留版本、反例、撤回与复议路径。

## 四层蒸馏法

任何外部做法进入 Agent Commons 前必须回答：

| 层 | 问题 | 输出 |
|---|---|---|
| 来源事实 | 原站明确写了什么？ | 带日期和链接的事实摘要 |
| 可迁移原则 | 它解决哪类普遍问题？ | 不绑定原站成员/技术名的原则 |
| 本地制度 | 怎样适配九位公民、议长和用户终审？ | Agent Commons 规则或候选规则 |
| 可测实验 | 什么指标证明它更好？ | 指标、期限、回退条件与负责人 |

外部方案不能凭“流行”直接改变 Agent Commons 架构。记录观察可以自动进行，规则和长期结构变化必须由用户确认。
